## 运行问题与处理

1. 原配置的 `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z` 拉取返回 401；同一版本 Docker Hub 官方镜像也无法访问。官方旧二进制校验文件请求返回 410。
2. [MinIO 官方仓库](https://github.com/minio/minio#source-only-distribution) 说明社区版已改为源码分发。已用 `docker/minio/Dockerfile` 从原配置相同的固定源码版本构建镜像，通过 `docker-compose.source-minio.yml` 启动；未使用第三方 MinIO 二进制。实际健康接口返回 HTTP 200。该历史版本仅用于复现现有本地环境，不代表线上维护方案。
3. 其余镜像拉取时，用户曾退出 Docker Desktop，拉取返回 `unexpected EOF`；重新打开后拉取完成。MySQL、Redis、Qdrant、MinIO、RocketMQ nameserver/broker 六个容器已运行，MySQL/Redis 健康检查通过，RocketMQ broker 已注册并建立原项目需要的两个主题。

Windows 中间件启动入口：在仓库根目录运行 `powershell -File scripts/dev-up.ps1 -SourceMinio`。不改系统默认 Java、不重装数据库、不清理已有 Redis 数据。此脚本本身不要求模型 Key 或 Tesseract。

后端 `/health` 返回 `UP`，已通过真实页面注册并登录两个本地测试账号。首次资料库读取曾受开发测试重新编译运行目录影响，已使用独立编译产物快照运行后端，恢复正常读取；这不作为业务逻辑改动。

首次分片上传受 C 盘空间不足阻塞，MinIO 返回 `XMinioStorageFull`。用户创建 D 盘可写目录后，已将本地对象存储及编辑任务临时目录移至该目录，并成功上传两段自制测试视频。`MINIO_DATA_DIR` 与 `EDITOR_TASK_ROOT` 支持此配置；原 C 盘数据保留，没有清理用户其他文件或降低存储保护阈值。

浏览器扩展另未开启“允许访问文件网址”，选择本地文件被扩展阻止。后续可通过真实 HTTP 分片上传继续服务端联调；此限制不记作网页上传通过。

尚未配置真实模型 Key。测试启动时，旧模型客户端只使用不可用的本机回环地址及明确的测试占位值，避免占位凭据发往真实服务；原模型功能保持未验收。新增时间戳 ASR 的代码和测试单独记录，字幕导入不计作 ASR 成功。
